  <name>Task 2: macOS launchd — _headscale service account creation + launchd plist review (R-03 MEDIUM-confidence path)</name>
  <what-built>
    The macOS launchd provisioning path in cmd_server_headscale.go's init command is complete but has been marked as a MEDIUM-confidence path by research (R-03). The code:
    1. Creates a dedicated _headscale service account via dscl (sudo) — check for existing account before running to be idempotent
    2. Creates /var/lib/headscale and /etc/headscale with chown to _headscale:_headscale
    3. Writes /Library/LaunchDaemons/net.abysslink.headscale.plist with UserName=_headscale, RunAtLoad=true, KeepAlive=true
    4. Runs launchctl load /Library/LaunchDaemons/net.abysslink.headscale.plist
    5. Probes ps -p $(pgrep headscale) -o user= and asserts result == "_headscale" (not root)

    Research confirmed: macOS post-Mojave allows non-root UserName in /Library/LaunchDaemons plists. listen_addr: ":443" (0.0.0.0:443) is required on macOS because binding a specific IP as non-root on port 443 fails. UID 399 is used for the _headscale account (ASSUMED — may conflict on some systems).
  </what-built>
  <how-to-verify>
    On a macOS test machine (Mojave+), run:
    1. `abysslink server headscale init --dry-run` — should print the full plan including the dscl commands without executing them
    2. `abysslink server headscale init --apply` — executes the provisioning (requires sudo for dscl and launchctl load)
    3. After init completes: `launchctl list net.abysslink.headscale` — should return a PID row (not just "-")
    4. `ps aux | grep headscale | grep -v grep` — the headscale process should be running as _headscale (not root)

    If the _headscale UID 399 conflicts on the test machine: change the UID to an unused value < 500 and re-run init. Document the chosen UID.
