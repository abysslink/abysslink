<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| go.mod → go toolchain | The `go` directive sets the minimum toolchain; a stale value leaves stdlib CVEs reachable |
| CI `go-version` → build environment | Workflow `go-version` pinning controls which compiler runs in CI; unpinned = can silently regress |
| go module proxy → go.sum | `go get` fetches from proxy.golang.org; go.sum pins the download hash |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-22-01 | Tampering | `net/textproto` (GO-2026-5039) — MIME header injection via daemon HTTP path | mitigate | Bump `go` directive to 1.26.4; fixes the stdlib package at source |
| T-22-02 | DoS | `crypto/x509` (GO-2026-5037) — inefficient hostname parse on attacker-controlled cert | mitigate | Bump `go` directive to 1.26.4; same fix as T-22-01 |
| T-22-03 | Tampering / DoS | `golang.org/x/crypto v0.50.0` — 13-CVE SSH batch (revoked-CA bypass, AES-GCM/Ed25519 panic, FIDO touch bypass) | mitigate | `go get golang.org/x/crypto@v0.52.0`; this is an indirect dep so no API changes needed |
| T-22-04 | Tampering | CI toolchain pinning — a stale `1.23` pin in workflows diverges from go.mod and can silently run vulnerable stdlib under CI green badge | mitigate | Align all 6 `go-version:` fields to `"1.26.4"`; SHA-pin actions/checkout + actions/setup-go in the two outlier files |
| T-22-SC | Tampering | npm/pip/cargo installs | accept | No new packages introduced this plan; only version bumps on existing Go stdlib + x/crypto indirect dep; Package Legitimacy Audit confirms no new packages (RESEARCH.md §Package Legitimacy Audit) |
