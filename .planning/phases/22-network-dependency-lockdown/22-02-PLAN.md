<objective>
Add three security validation rules to config.Validate, closing NET-02 (cleartext PAT guard)
and NET-03 (flag-injection / hostname charset gate) in full, including the watch pane name
vector explicitly called out in D-06:

NET-02: NetBird `server_url` must begin with `https://` — mirrors the existing Headscale guard
at config.go:623 verbatim. Prevents the NetBird PAT from being transmitted in cleartext.

NET-03 (hostname + server_url): `tailnet.hostname` and the hostname component of each backend
`server_url` must match the DNS-safe charset regex (`^[a-z0-9][a-z0-9\-.]{0,252}[a-z0-9]$`).
Prevents a config value beginning with `-` from being parsed as a flag by `tailscale up`/`set`.
The regex is inlined as `safeHostnamePat` in config.go to avoid the confirmed
`config→fleet→config` import cycle.

NET-03 (watch panes — D-06): Each element of `cfg.Modules.Watch.Panes []string` (config.go:251)
passes through `daemon/server.go:333` directly to `tmux capture-pane -t <pane>`. A value such as
`-kill-server` would be parsed as a tmux flag (A8 / same class as hostname injection). D-07
mandates a single gate at config.Validate — `validateWatchPanes` runs the same `safeHostnamePat`
check over every element of the slice. No daemon change is needed beyond this config gate.

Purpose: D-07 mandates a single gate at config.Validate. If config validates, all downstream
argv construction is safe by construction — no defensive re-check at call sites.

Output: Modified config.go + new test cases covering every accept/reject path in VALIDATION.md.
</objective>
