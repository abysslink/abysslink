<objective>
Migrate the Web UI CSRF protection off the unmaintained `github.com/gorilla/csrf`
(CVE-2025-47909 — no upstream fix) to the stdlib `net/http.CrossOriginProtection` (Go 1.26),
removing both `gorilla/csrf` and `gorilla/securecookie` from the module graph entirely (DEP-03 /
D-08 / D-09 path (b) — the only viable path, per RESEARCH.md).

The migration replaces `newSafewebServer` + the safeweb import in three files with two new
functions — `securityHeadersMiddleware` (reproduces safeweb's 5 non-CSRF security headers:
CSP, HSTS, X-Content-Type-Options, Referer-Policy, COOP) and `buildWebHandler` (wires
CrossOriginProtection → securityHeaders → mux, drop-in for `sw`). The form template token
and the `CSRFField` struct field are removed since CrossOriginProtection is stateless (no
hidden token required).

The existing `webui-csrf` doctor probe (TestWebuiCSRFCheck) still returns 403 — as
confirmed in RESEARCH.md Pitfall 2, the 403 comes from `whoIsMiddleware` rejecting the
loopback probe address, not from gorilla/csrf. This is preserved unchanged.

Purpose: Removes a CVE with no upstream fix path; reduces the module graph attack surface.
Output: Modified server.go, handlers.go, deps_webui.go, notify.html; gorilla-free go.mod.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser (tailnet) → POST /notify | Cross-origin POST could trigger notification delivery if CSRF protection is bypassed |
| go.mod → module graph | Gorilla/csrf CVE-2025-47909 is only exploitable if the package is imported; removing it from the graph eliminates the attack surface entirely |
| securityHeadersMiddleware → HTTP response | Security headers (CSP, HSTS, COOP) enforce browser-side protections against XSS/clickjacking/protocol downgrade |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-22-12 | Spoofing | `github.com/gorilla/csrf` CVE-2025-47909 — TrustedOrigins compares host only, ignores scheme; HTTP origin accepted when HTTPS intended; no upstream fix | mitigate | Remove gorilla/csrf entirely; replace with `net/http.CrossOriginProtection` (stdlib Go 1.26) which checks Sec-Fetch-Site header — stateless, no scheme-confusion flaw (A12) |
| T-22-13 | Spoofing | CrossOriginProtection behavior with no Sec-Fetch-Site header (non-browser/doctor probe) | accept | Per RESEARCH Pitfall 2 verified: requests without Sec-Fetch-Site are treated as same-origin/non-browser and allowed; the doctor probe gets 403 from whoIsMiddleware (loopback rejection), not CSRF layer — posture preserved |
