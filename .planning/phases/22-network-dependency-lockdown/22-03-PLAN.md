<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Docker daemon → ntfy container port bindings | The `-p` flags in docker run determine which interfaces ntfy is reachable on; a loopback mapping makes ntfy reachable by any local process/SSH-forward |
| Local network → ntfy HTTP port | A loopback bind on a multi-user system (or SSH session) makes ntfy controllable by anyone who can connect to 127.0.0.1 |
| shell.Runner → docker inspect output | Doctor reads back the actual binding configuration; any mismatch = FATAL |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-22-09 | Elevation of Privilege | `ntfy/module.go:401` — `-p 127.0.0.1:<port>:80` publishes ntfy on loopback; any local user/SSH-tunnel can POST notifications or drain subscription | mitigate | Remove the loopback `-p` argv pair entirely (D-01); keep only tailnet-IP mapping; immutable floor enforced by doctor ntfyBindCheck FATAL (A1) |
| T-22-10 | Elevation of Privilege | docker inspect FATAL-on-error — if doctor cannot inspect the container, a misconfigured binding is invisible | mitigate | ntfyBindCheck returns FATAL (not OK-with-warning) when docker inspect fails; fail-closed posture (D-02 PRIMARY) |
| T-22-11 | Elevation of Privilege | Loopback bind reintroduction — future code change re-adds the loopback `-p` without triggering a CI regression | mitigate | ntfyLoopbackReachCheck provides live-dial corroboration; TestNtfyBindCheck with MockRunner ensures the module.go argv is exercised in tests (TestDockerRun assertion update from VALIDATION.md NET-01a) |
| T-22-SC | Tampering | npm/pip/cargo installs | accept | No new packages; cmd_doctor_ntfy.go uses only stdlib (context, fmt, net, strings) + existing internal packages (config, modules, shell) |
</threat_model>
