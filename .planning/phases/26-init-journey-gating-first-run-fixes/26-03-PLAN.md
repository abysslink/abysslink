<objective>
Fix the two UAT-reported interactive-init defects (multiple sudo password prompts and journey
appearing stuck) by correcting the stdio paths for privileged commands and eliminating a
redundant pmset invocation in the power module.

Purpose: Interactive `abysslink init` on macOS produces multiple sudo password prompts and
sometimes freezes due to three compounding defects identified in the debug sessions:
(1) sudo calls in maybeFixFirewall/maybeFixSleep go through runner.Run, which buffers
stdout/stderr and nulls stdin — macOS sudo's tty-keyed credential cache cannot reuse the
timestamp across calls where the controlling tty is unreachable via std fds;
(2) power/module.go applyDarwin has no already-disabled check, so `up --apply` re-runs
`sudo pmset` in a separate child process even when sleep is already disabled by init;
(3) journeyOfferRun spawns runner.RunInteractive immediately after huh.NewConfirm.Run()
returns, but huh leaves the terminal in raw mode — the child inherits a dirty terminal
state, causing keystroke-swallowing and rendering glitches.

Output: Modified mock.go, cmd_init.go, journey.go, power/module.go, and their test files.
All changes are behavior-only; no new Go dependencies, no interface changes.
</objective>
