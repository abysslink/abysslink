<objective>
Fix the two silent first-run bugs in `abysslink init`:

**B1** — `openURL` on macOS silently does nothing and returns nil (reports "Browser opened" when no browser opened). Root cause: `isCommandAvailable` probes with `--version`; `open --version` exits 1; `ExecRunner.Run` converts ExitError → `(Result, nil)`; so `err == nil` even though the binary rejected the probe. Fix: replace `isCommandAvailable` with `shell.LookPath` (PATH probe — no subprocess) and delete the broken helper. Also fix `openURL` to return an error when the opener exits non-zero, and to return an explicit error when no opener is found (instead of silent `return nil`).

**B3** — `checkACSleepDisabled` never returns true on real macOS output because `pmset -g` emits lines like `sleep  0 (sleep prevented by powerd)` — more than 2 fields — but the parser requires exactly 2. Fix: change `len(fields) == 2` to `len(fields) >= 2`.

Purpose: These bugs cause `abysslink init` to print false-success messages on first run: browser never opens for Tailscale auth, and `sudo pmset` re-runs on every init because sleep is never detected as already disabled.

Output: `shell.LookPath` function, patched `openURL`, deleted `isCommandAvailable`, patched `checkACSleepDisabled`, and regression tests covering both fixes.
</objective>

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-26-01 | Tampering | openURL binary selection | mitigate | shell.LookPath checks only two known-safe binaries: "open" (macOS) and "xdg-open" (Linux). No user-supplied binary name. No sh -c. Argv exec direct. |
| T-26-02 | Information Disclosure | openURL false success message | mitigate | B1 fix: openURL now returns error when opener is absent or exits non-zero; caller prints "Could not open browser — visit manually" instead of false "Browser opened" |
