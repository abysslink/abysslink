  <behavior>
    ENTRY POINT:
    - `func pushGatewayDoctorFindings(ctx context.Context, cfg *config.Config) []modules.Finding`
    - Called from `collectDoctorFindings` in cmd_doctor.go (append after contentStoreDoctorFindings call — read cmd_doctor.go to find the exact insertion point)
    - Module constant: `const pushGatewayModule = "push-gateway"`
    - Three helper constructors: `pushOKFinding`, `pushWarnFinding`, `pushFatalFinding` (matching contentstore pattern)

    THE 9 CHECKS (evaluated in this order):

    1. `push-creds-keychain` (PUSH-06 / D-03):
       - Call `fetchDaemonStatus(ctx)` to get the daemon's `gateway_creds_status` field (new field added in Plan 04 to `statusDaemonExtras` and `daemonStatusResponse`)
       - If daemon unreachable → WARN "abysslinkd not reachable — cannot verify gateway creds from daemon context (start it: abysslink daemon enable --apply)"
       - If `gateway_creds_status == "ok"` → OK "gateway credentials loaded successfully"
       - If `gateway_creds_status == "unavailable"` → WARN "gateway credentials are not loaded in daemon context — push delivery will fail (check creds_source configuration)"
       - Absent field (older daemon) → OK "gateway-creds-unknown: daemon reachable but did not report creds status (older daemon)"

    2. `push-creds-file-perms` (PUSH-06 / D-04):
       - Only check if `cfg.Notify.Gateway.APNs.KeySource == "file"` or `cfg.Notify.Gateway.FCM.CredsSource == "file"`
       - `credsPath` from config (the file path — add a `CredFilePath string` field to the gateway config struct, or derive from XDG_STATE_HOME convention)
       - `os.Stat(credsPath)` → if missing: FATAL "gateway creds file not found at <path>"
       - `info.Mode().Perm() != 0o600` → FATAL "gateway creds file mode is <actual> — must be 0600"
       - `info.Mode().Perm() & 0o044 != 0` → FATAL "gateway creds file is group/world-readable"
       - All OK → OK "gateway creds file permissions OK (0600)"
       - If neither leg is configured with `creds_source: file` → skip (return no finding for this check, or emit OK "not configured with file creds source")

    3. `push-creds-file-location` (PUSH-06 / D-04):
       - Only if file creds are configured
       - Check if `credsPath` starts with known cloud-sync dirs: `~/Library/Mobile Documents/` (iCloud Drive), `~/Dropbox/`, `~/OneDrive/`, `~/.dropbox/` — expand `~` via `os.UserHomeDir()`
       - If in synced location → FATAL "gateway creds file is in a cloud-synced directory (<path>) — credentials may be uploaded to cloud; move to ~/.local/state/abysslink/"
       - Otherwise → OK

    4. `push-apns-experimental` (D-14):
       - If `cfg.Notify.Gateway.APNs.Enabled` → WARN "APNs push leg is enabled and experimental — the v5 mobile app receiver has not yet shipped; deliveries will fail without the NSE installed"
       - Else → OK "APNs leg is disabled (default — experimental until v5 app ships)"

    5. `push-fcm-experimental` (D-14):
       - Same pattern for FCM leg

    6. `push-apns-bundle-missing` (research Q1):
       - If `cfg.Notify.Gateway.APNs.Enabled && cfg.Notify.Gateway.APNs.BundleID == ""` → FATAL "APNs is enabled but notify.gateway.apns.bundle_id is empty — set it to your app's bundle identifier (e.g. dev.abysslink.app)"
       - Else → (no finding — schema validation already catches this; but doctor provides a runtime catch)

    7. `push-stale-tokens` (D-12):
       - Read device store (same as `localDeviceEntries()` pattern in cmd_status.go) — list devices and check `last_seen` against 30-day threshold
       - Any device with `last_seen > 30 days` → WARN "device <name> last seen <duration> ago — push token may be stale; re-enroll or revoke: abysslink enroll phone --revoke <device>"
       - All OK → OK "no stale device push tokens"

    8. `push-unifiedpush-ntfysh` (D-15 direction 1):
       - Read device store; for each device with `platform == "unifiedpush"`, check if `provider_token` URL host == "ntfy.sh" or ends with ".ntfy.sh"
       - If any → WARN "UnifiedPush endpoint routes through ntfy.sh (a third party) — wake titles are visible to ntfy.sh; use a self-hosted ntfy server for sovereignty"
       - The `isPublicNtfyEndpoint(url string) bool` helper from PATTERNS.md §cmd_doctor_push.go
       - If none or no unifiedpush devices → OK "UnifiedPush endpoints are self-hosted (sovereign)"
       - NOTE: device store provider_token access — follow D-17: read it only for URL parsing, never log it

    9. `push-ios-unifiedpush-gap` (D-15 direction 2):
       - Always emit this WARN when UnifiedPush is enabled and APNs is NOT enabled: "UnifiedPush (sovereign path) does NOT cover iOS — iOS requires the APNs leg (or ntfy.sh relay). Enable notify.gateway.apns if you need iOS wake delivery."
       - If APNs IS enabled → no warning (iOS covered by APNs)
       - If neither UnifiedPush enabled nor APNs enabled → skip (nothing to warn about)

    10. `push-contentstore-bind` (D-16):
        - Call `fetchDaemonStatus(ctx)`; check `extras.ContentStore` string
        - If content store reports "listening on 0.0.0.0:*" or "listening on <public-IP>:*" → FATAL "content store is bound to a public address (<bind>) — MUST bind to the tailnet IP only; restart abysslinkd with correct content_store.bind_addr"
        - `isPublicBind(addr string) bool`: `strings.HasPrefix(addr, "0.0.0.0") || (!strings.HasPrefix(addr, "100.") && !strings.HasPrefix(addr, "[fd7a:") && !strings.HasSuffix(addr, ".ts.net"))` — simple heuristic; tailnet IPs are 100.x.x.x (CGNAT) or MagicDNS .ts.net
        - If daemon unreachable → WARN (same as push-creds-keychain)
        - If listening on tailnet IP → OK

    TESTS (using `withStubDaemonStatus` pattern from contentstore tests):
    - `TestDoctorPushCredsOK`: stub returns `gateway_creds_status: "ok"` → OK finding
    - `TestDoctorPushCredsDaemonDown`: stub returns error → WARN finding

    - `TestDoctorPushContentStoreTailnetBind`: stub returns `content_store: "listening on 100.64.1.5:2587"` → OK finding
