    The approve subcommand has two flags:
    - --check: parse PreToolUse hook JSON from stdin; extract tool_name + tool_input; call daemon IPC; block; exit 0 (approved) or exit 2 (denied per bug #19298 workaround)
    - --blocking: modifies --check to use the full timeout from cfg.Approval.TimeoutSeconds; without --blocking the check returns immediately (for testing)
    - --permission-request: parse PermissionRequest hook JSON from stdin; fire notification asynchronously (POST /notify via unix socket); write allow JSON to stdout immediately; exit 0

    PreToolUse hook stdin JSON format (RESEARCH.md Pattern 7):
    {session_id, transcript_path, cwd, hook_event_name, tool_name, tool_input:{command:string}}
    Parse: only tool_name and tool_input.command are used for the closure-hash-like identifier.

    PermissionRequest hook stdin JSON (RESEARCH.md Pattern 7):
    {session_id, tool_name, tool_input:{...}, hook_event_name:"PermissionRequest", ...}
    Parse: tool_name only (for the notification title).

    PreToolUse --check implementation:
    - Read JSON from stdin; parse tool_name and tool_input
    - Build a synthetic closure descriptor: "claude:"+tool_name+":"+json(tool_input) (not a binary exec; treated as an action name by the approve registry)
    - Connect to daemon unix socket with context.WithTimeout(ctx, 5s) for the connection phase; if daemon unreachable → exit 2 (deny, per D-10 headless-deny)
    - POST /approve/request with JSON {action: tool_name, closure_hash: sha256hex(tool_name+tool_input_json), declared_tier: TierSensitive=1, extra_critical: cfg.Approval.ExtraCritical}
    - If 403 (critical tier): write to stderr "approve: critical action — TTY approval required"; exit 2
    - GET /approve/wait/{request_id} with context timeout from cfg.Approval.TimeoutSeconds
    - On 200 {approved:true}: exit 0
    - On 200 {approved:false} or 408 or error: exit 2
    - Exit code 2 is the PreToolUse blocking mechanism per Claude Code docs + #19298 workaround

    PermissionRequest --permission-request implementation:
    - Read JSON from stdin; parse tool_name
    - Fire notification asynchronously: POST /notify on unix socket with v2 payload {kind:"approval_request", title:"approve "+tool_name+" ?"} — fire-and-forget goroutine; main goroutine does NOT wait
    - Return immediately: write allow JSON to stdout: {"hookSpecificOutput":{"hookEventName":"PermissionRequest","decision":{"behavior":"allow"}}}
    - Exit 0 (fast path per #12176 workaround — the PermissionRequest hook must return within ~1s)

    Note: the abysslink approve subcommand reads from STDIN (per CLAUDE.md: "no secrets on argv"). The tool_input (which may contain bash commands) is read from stdin, never a flag.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Claude Code hook→abysslink approve stdin | tool_name and tool_input arrive via stdin (not argv per CLAUDE.md); tool_input may contain arbitrary bash commands — treated as data for hashing, never eval'd |
| abysslink approve→daemon unix socket | unix socket is local-only; connection timeout prevents indefinite block on unreachable daemon |
| PermissionRequest hook stdout | allow JSON written to stdout is the hook's decision — must return within ~1s (bug #12176 workaround) |
