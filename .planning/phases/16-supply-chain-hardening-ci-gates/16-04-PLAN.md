**internal/cli/cmd_verify.go — new file:**

Apache-2.0 license header required. Package `cli`.

Implement `newVerifyCmd() *cobra.Command`:
- Use: `verify`
- Short: `Verify the installed binary's cosign signature and SLSA provenance`
- Example showing `abysslink verify` and `abysslink verify --json`
- Flags: `--json` (bool, default false); `--bundle` (string, default "", overrides the auto-detected bundle path); `--version` (string, default current `version`, overrides which release version to verify against)

The command logic:
1. Determine the bundle file path: if `--bundle` provided, use it. Otherwise construct the expected bundle URL for the current `version`: `https://github.com/abysslink/abysslink/releases/download/v{version}/abysslink_{bare-version}_checksums.txt.bundle` — download it to a temp file.
2. Determine the checksums file URL: `https://github.com/abysslink/abysslink/releases/download/v{version}/abysslink_{bare-version}_checksums.txt` — download it to a temp file.
3. Call `verifyCosignBundle(ctx, runner, checksumPath, bundlePath)` — this is a new helper function (see below).
4. Attempt SLSA provenance check: query the GitHub attestations API `https://api.github.com/repos/abysslink/abysslink/attestations/sha256:{digest}` where digest is the sha256 of the checksums file. Parse the response to confirm a SLSA provenance attestation exists. If the API returns 200 with at least one attestation, set `slsaOK = true`. If it returns 404 or any error, set `slsaOK = false` (do not fail — provenance check is informational; only bundle verify is required to succeed).
5. Output via Printer. If `--json`, emit JSON with: `bundle_ok`, `slsa_ok`, `version`, `commit`. If human, emit colored status lines using existing style constants.

**verifyCosignBundle helper** (add to cmd_verify.go or a new internal helper — do not put it in cmd_upgrade.go yet):

```go
// verifyCosignBundle verifies a cosign v3 bundle file against a target artifact.
// Uses --offline flag so Rekor is not required (Pitfall 14 mitigation).
func verifyCosignBundle(ctx context.Context, runner shell.Runner, target, bundleFile string) error {
    res, err := runner.Run(ctx, "cosign", "verify-blob",
        "--bundle", bundleFile,
        "--offline",
        "--certificate-identity-regexp", upgradeIdentityRegexp,
        "--certificate-oidc-issuer", upgradeOIDCIssuer,
        target,
    )
    if err != nil {
        return fmt.Errorf("cosign verify-blob: %w", err)
    }
    if res.ExitCode != 0 {
        combined := strings.TrimSpace(res.Stdout + res.Stderr)
        return fmt.Errorf("cosign verify-blob exited %d: %s", res.ExitCode, combined)
    }
    return nil
}
```

The constants `upgradeOIDCIssuer` and `upgradeIdentityRegexp` are already defined in cmd_upgrade.go — reference them (they are in the same `cli` package, so no import needed).

**Check: supply-cosign-bundle**

Severity: `modules.SeverityWarning` on failure (not Fatal — the binary runs fine without a verifiable bundle; this is an integrity advisory check per the doctor check severity conventions already in the codebase).

Logic:
1. Find the self executable path via `os.Executable()`.
2. Determine the expected bundle URL: construct from `version` ldflag — `https://github.com/abysslink/abysslink/releases/download/v{version}/abysslink_{bare-version}_checksums.txt.bundle`. If `version` is "dev" or "unknown", emit SeverityWarning with message "supply-cosign-bundle: dev build, no release bundle available".
3. Attempt to download the bundle to a temp file (use `downloadFile` from cmd_upgrade.go — same package).
4. Download the checksums file similarly.
5. Call `verifyCosignBundle(ctx, runner, checksumPath, bundlePath)`.
6. If verification succeeds: emit `SeverityOK`, check: "supply-cosign-bundle", message: "cosign v3 bundle verified (offline)".
7. If verification fails: emit `SeverityWarning`, check: "supply-cosign-bundle", message: "cosign bundle verification failed: {err}".

The check must use a `shell.Runner` passed to it — look at how other doctor checks receive the runner (likely via the `modules.Deps` or similar context struct). Mirror the existing pattern exactly. Do not call `exec.Command` directly.

**Check: supply-slsa-source**

Severity: `modules.SeverityWarning` on failure.

Logic:
1. If `slsaURL` ldflag is empty: emit SeverityWarning, message: "no SLSA provenance URL embedded (dev build or pre-v3 release)".
2. If `slsaURL` is non-empty: the check passes — emit SeverityOK, message: "SLSA L2 provenance available at {slsaURL}". (Full attestation fetch would require network; the doctor check is lightweight — presence of the URL is sufficient evidence for WARN-level tracking. The `abysslink verify` command does the full network check.)

Register both checks under module name `"supply"`.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| abysslink verify → network (GitHub API + release CDN) | Fetches bundle and checksums over HTTPS; MITM could serve wrong bundle |
| install.sh → GitHub releases CDN | Downloads .bundle file; CDN compromise could serve wrong bundle |
| shell.Runner → cosign process | cosign is an external binary; version pinned in CI but not in user environment |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-16-14 | Spoofing | install.sh fails open when cosign absent | mitigate | sha256 checksum is always verified; cosign is advisory (warn not die when absent); bundle downloaded unconditionally so cosign users get v3 verification |
| T-16-15 | Tampering | cosign v2 .sig/.cert in upgrade path — Rekor required | mitigate | upgrade verifyCosignBlob updated to v3 --bundle --offline; no Rekor dependency |
| T-16-16 | Repudiation | No audit log entry for abysslink verify | accept | verify is read-only; no mutation; audit log is for mutations only (CLAUDE.md hard rule: audit writes for file mutations) |
| T-16-17 | Information Disclosure | slsaURL / bundleURL exposed in version --json | accept | these are public release artifact URLs; no secrets |
| T-16-18 | Elevation of Privilege | doctor check calls cosign via exec | mitigate | all exec goes through shell.Runner (CLAUDE.md rule); mockable in tests |
