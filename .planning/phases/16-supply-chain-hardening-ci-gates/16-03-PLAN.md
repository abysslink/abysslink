Read the current .goreleaser.yaml (modified by Plan 02). Locate the `signs:` stanza. Replace it entirely with the cosign v3 bundle format.

**Current (v2) stanza produces .sig and .pem — REPLACE:**
```yaml
signs:
  - cmd: cosign
    certificate: "${artifact}.pem"
    args:
      - sign-blob
      - "--output-certificate=${certificate}"
      - "--output-signature=${signature}"
      - "${artifact}"
      - "--yes"
    artifacts: checksum
    output: true
```

**New (v3 bundle) stanza — emit .bundle file per SCH-03 / Pitfall 14:**
```yaml
signs:
  - cmd: cosign
    args:
      - sign-blob
      - "--bundle=${artifact}.bundle"
      - "--yes"
      - "${artifact}"
    artifacts: checksum
    output: true
```

Key changes:
- Remove `certificate:` field — bundles embed the certificate; no separate .pem file
- Remove `--output-certificate` and `--output-signature` args
- Add `--bundle=${artifact}.bundle` — produces a single self-contained bundle file per cosign v3 spec
- The `--yes` flag suppresses the interactive OIDC prompt in CI (required for non-interactive signing)
- `artifacts: checksum` — signs the checksums.txt manifest (same as before); individual archives are verified transitively via the manifest

The bundle file is a JSON envelope containing the certificate chain, the Rekor log entry proof, and the signature. Offline verification via `cosign verify-blob --bundle <file> --offline` does not require Rekor reachability (Pitfall 14 mitigation). The bundle is published as a release asset alongside the binary.

After editing, validate: `python3 -c "import yaml; yaml.safe_load(open('.goreleaser.yaml'))"` must exit 0.

**Job 2: sign**

```yaml
  sign:
    name: Sign (cosign v3 bundle)
    needs: build
    runs-on: ubuntu-latest
    timeout-minutes: 30
    permissions:
      contents: write     # upload release assets
      id-token: write     # OIDC token for cosign keyless signing
    steps:
      - name: Harden runner
        uses: step-security/harden-runner@<SHA> # v2.17.0
        with:
          egress-policy: block
          allowed-endpoints: >
            api.github.com:443
            objects.githubusercontent.com:443
            github.com:443
            fulcio.sigstore.dev:443
            rekor.sigstore.dev:443
            oauth2.sigstore.dev:443
            token.actions.githubusercontent.com:443
            tuf-repo-cdn.sigstore.dev:443

      - name: Download dist artifacts
        uses: actions/download-artifact@<SHA> # v4.3.0
        # Pinned SHA: executor must resolve via: gh api repos/actions/download-artifact/git/refs/tags/v4.3.0
        with:
          name: dist
          path: dist/

      - name: Install cosign
        uses: sigstore/cosign-installer@<SHA> # v3.8.2 (cosign v3.0.6)
        # Pinned SHA: executor must resolve via: gh api repos/sigstore/cosign-installer/git/refs/tags/v3.8.2
        with:
          cosign-release: v3.0.6

      - name: Sign checksums with cosign v3 bundle
        run: |
          # cosign v3: --bundle produces a self-contained bundle (cert + proof + sig)
          # --offline verification works from the bundle file alone (Pitfall 14 mitigation)
          for checksums_file in dist/*checksums.txt; do
            cosign sign-blob \
              --bundle="${checksums_file}.bundle" \
              --yes \
              "${checksums_file}"
          done

      - name: Upload .bundle files to GitHub Release
        env:
          GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}
        run: |
          tag="${{ needs.build.outputs.version }}"
          for bundle in dist/*.bundle; do
            gh release upload "${tag}" "${bundle}" --clobber
          done
```

**Job 3: attest**

```yaml
  attest:
    name: SLSA L2 Provenance (actions/attest@v4)
    needs: build
    runs-on: ubuntu-latest
    timeout-minutes: 30
    permissions:
      contents: read
      attestations: write  # publish SLSA provenance attestation
      id-token: write      # OIDC token required by actions/attest
    steps:
      - name: Harden runner
        uses: step-security/harden-runner@<SHA> # v2.17.0
        with:
          egress-policy: block
          allowed-endpoints: >
            api.github.com:443
            objects.githubusercontent.com:443
            github.com:443
            fulcio.sigstore.dev:443
            rekor.sigstore.dev:443

      - name: Download dist artifacts
        uses: actions/download-artifact@<SHA> # v4.3.0
        with:
          name: dist
          path: dist/

      - name: Generate SLSA L2 provenance
        uses: actions/attest@<SHA> # v4.1.4 — SLSA Build L2
        # Pinned SHA: executor must resolve via: gh api repos/actions/attest/git/refs/tags/v4.1.4
        with:
          subject-path: |
            dist/*_checksums.txt
            dist/*.tar.gz
            dist/*.zip
            dist/*.deb
            dist/*.rpm
          # Binds attestation to the exact source commit SHA (Pitfall 15 mitigation)
          # github.sha is the triggering tag's commit SHA — immutable for tag pushes
          github-token: ${{ secrets.GITHUB_TOKEN }}
```

**Implementation notes for the executor:**
- All `<SHA>` placeholders MUST be resolved to real 40-character commit SHAs before writing the file. Use `gh api repos/<owner>/<repo>/git/refs/tags/<tag>` or `gh api repos/<owner>/<repo>/git/ref/tags/<tag>` to get the object SHA, then if the object type is `tag` (annotated), dereference via `gh api repos/<owner>/<repo>/git/tags/<sha>` to get the commit SHA. For actions specifically, the SHA needed is the commit SHA the tag points to.
- The `sign` job does NOT build from source — it downloads pre-built artifacts from `build` and adds signatures. It has no access to source code.
- The `attest` job does NOT sign binaries — it generates a SLSA provenance attestation document referencing the subject files. It also downloads pre-built artifacts, not source.
- The separation is critical: no single job has both `id-token: write` and source checkout with write access.
- `timeout-minutes: 30` on every job (per Pitfall 17: prevents hung job holding high-privilege token indefinitely).
- `packages: write` is removed — this project does not use GitHub Container Registry.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| build job → sign job | Artifacts pass through GitHub Actions artifact store; integrity is protected by OIDC signing in sign job |
| GitHub OIDC → Fulcio | OIDC token minted by Actions; Fulcio issues short-lived signing certificate |
| Rekor transparency log | External service; offline bundle verification ensures installer does not depend on Rekor availability |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-16-09 | Elevation of Privilege | Single job with id-token:write + contents:write + source access (Pitfall 17) | mitigate | three-job split: build (contents:read), sign (id-token:write + contents:write, no source), attest (attestations:write) |
| T-16-10 | Tampering | Cosign v2 .sig/.cert format — Rekor required for offline verify (Pitfall 14) | mitigate | v3 bundle embeds Rekor proof; cosign verify-blob --bundle --offline succeeds without Rekor connectivity |
| T-16-11 | Tampering | SLSA provenance bound to mutable branch ref not commit SHA (Pitfall 15) | mitigate | actions/attest@v4 uses github.sha which is the immutable commit SHA for tag pushes |
| T-16-12 | Denial of Service | Hung release job holds id-token:write indefinitely | mitigate | timeout-minutes: 30 on every job; token auto-expires at job end |
| T-16-13 | Tampering | goreleaser-action mutable tag reference | mitigate | all action uses: pinned to 40-char commit SHA; dependabot keeps them current |
| T-16-SC | Tampering | npm/pip/cargo installs | accept | release workflow installs no npm/pip packages; cosign and syft are Go binaries installed via their own actions |
</threat_model>
